Case Study

PaaS Self-Service Deployment Console

A self-service internal developer platform that takes a reviewed git commit and turns it into a running AWS Lambda service — complete with automated code-quality gating, human approval, containerised builds, and one-click deployment — without anyone touching the AWS console by hand.

◆ The Problem

Turning a reviewed commit into a running cloud service usually means manually building a Docker image, pushing it to a container registry, and hand-writing infrastructure-as-code for a Lambda function, its trigger (a schedule or an HTTP endpoint), and its permissions — slow, repetitive, and easy to get wrong. There's also no consistent gate to stop unreviewed or low-quality code from reaching production.

This proof-of-concept collapses that entire path into a single console: submit a commit, get it approved against an automated quality scan, build it, and deploy it — as either a scheduled job or a public API — in a few clicks.

◆ How It Works

1

Request Approval

A developer submits a specific commit from a repository for review. This automatically triggers an automated SonarCloud code-quality scan.

2

Review

An admin opens the Review Queue, checks the quality scan result and request notes, then approves or rejects that exact commit.

3

Build

Once approved, the developer packages that commit into a container image via Docker and pushes it to Amazon ECR.

4

Deploy

The built image becomes a live AWS Lambda function — either on a repeating schedule via EventBridge (Cron), or reachable as an HTTP endpoint via API Gateway — provisioned automatically with AWS CDK.

5

Done

The result of every step — success or error — is shown directly on the page, no CLI or AWS console required.

The frontend is a plain React + Vite single-page app with no state-management library, talking to a local FastAPI backend over REST. The backend owns three flows: cloning & building a repo into a Lambda-compatible container image, deploying that image behind a scheduled EventBridge trigger, and deploying it behind an API Gateway HTTP endpoint — both provisioned through AWS CDK.

◆ Good to Know

As a proof-of-concept rather than a finished product, a few things are intentionally out of scope for now:

  • No login or user-account system — anyone with the URL can use it.
  • No persistence — refreshing the browser clears any in-progress form.
  • The Review Queue doesn't auto-refresh; a manual refresh shows the latest status.
