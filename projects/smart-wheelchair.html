Smart Wheelchair: Multi-Modal Control Interface

A final-year research project at the University of Moratuwa: a conventional wheelchair retrofitted with three ways to drive it: voice, hand gesture, and the standard joystick, so the interface adapts to the range of motor ability a user actually has, instead of assuming everyone can operate a joystick.

◆ The Problem

Most powered wheelchairs assume the user can reliably operate a joystick: fine motor control in one hand, sustained over the whole trip. That assumption excludes a meaningful group of users with more severe mobility impairments, who can move a limb roughly or speak clearly, but can't manage the continuous precision a joystick demands. For them, a joystick-only chair isn't a mobility aid, it's a barrier.

As a final-year research project (batch G19-13, Department of Electrical Engineering, University of Moratuwa), we set out to build a wheelchair that meets the user where their ability is: the same conventional joystick for those who can use it, a hand-gesture interface for those with coarser motor control, and a voice interface for hands-free operation, all driving the same chair through one unified control layer.

◆ How It Works

1

Joystick Input

The conventional analog joystick remains available as the baseline interface for users who retain enough fine motor control to use it, and as a familiar fallback if another mode misreads a command.

2

Gesture Input

Hand and arm movements are captured and classified into directional commands, giving users with limited hand dexterity a way to drive the chair without gripping or precisely steering a joystick.

3

Voice Input

Spoken directional commands are recognised on-board and mapped to the same command set, enabling fully hands-free operation for users with limited limb mobility.

4

Unified Control Layer

Regardless of which interface is active, every input is normalised into the same forward / back / left / right / stop instruction set before it reaches the motor driver, so switching modes never changes how the chair actually responds.

5

Motor Response

The motor driver circuit translates the normalised command into motion, moving the wheelchair accordingly.

Each of the three input interfaces is treated as an independent front-end to the same control unit: whichever one is active resolves its raw input (a joystick position, a classified gesture, or a recognised voice command) down to a single shared command, which the control unit forwards to the motor driver. Keeping the mapping layer common to all three interfaces meant the team could build and tune each input mode independently without touching how the chair itself moves.

◆ Good to Know

As a university research prototype rather than a commercial product, a few things are worth keeping in mind:

  • Built and evaluated as a proof-of-concept on a single physical prototype, not tested across a range of users or wheelchair models.
  • The joystick interface is retained throughout as a familiar, reliable fallback whenever gesture or voice recognition is uncertain.
  • Full methodology, evaluation results, and hardware detail are documented in the published paper rather than repeated here.
